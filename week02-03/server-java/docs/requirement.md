# 요구사항
## 기능적 요구사항
- 콘서트 예약 서비스를 제공한다.
- 대기열 시스템을 제공하고, 예약 서비스는 작업 가능한 유저만 수행할 수 있다.
- 좌석 예약 요청 시, 결제가 이루어지지 않더라도 일정 시간동안 다른 유저가 해당 좌석에 접근할 수 없다.
- 서비스 이용을 위한 토큰을 발급 받을 수 있다.
  - 토큰은 사용자 식별자와 해당 유저의 대기열을 관리할 수 있는 정보 (대기 순서, 잔여 시간 등)을 포함한다.
  - 모든 API는 해당 토큰을 이용해 대기열 검증을 통과해야 이용할 수 있다.
  - 대기열 검증은 기본적으로 폴링으로 동작하나, 다른 방안도 고려해볼 수 있다.
- 예약 가능 날짜 목록을 조회할 수 있다.
- 예약 가능 좌석을 조회할 수 있다.
  - 날짜 정보를 입력받아 예약 가능한 좌석정보를 조회한다.
  - 좌석 정보는 1~50까지의 좌석번호로 관리한다.
- 좌석 예약 요청을 할 수 있다.
  - 좌석 예약과 동시에 예약된 좌석은 해당 유저에게 5분간 임시 배정된다. (정책에 의해 자율적으로 정의 가능)
  - 만약 임시 배정 시간 내에 결제가 완료되지 않는다면 임시 배정은 해제되며, 다른 사용자가 예약 가능해진다.
- 서비스 이용을 위한 포인트(잔액) 충전을 할 수 있다.
  - 사용자 식별자 및 충전할 금액을 받아 잔액을 충전한다.
- 서비스 이용을 위한 포인트를 조회할 수 있다.
  - 사용자 식별자를 통해 조회한다. 
- 콘서트 예약 시, 포인트 혹은 그 외 수단을 사용해서 결제를 할 수 있다.
  - 결제 완료 시, 결제 내역을 생성한다.
  - 결제 완료 시, 해당 좌석의 소유권을 유저에게 배정하고 대기열 토큰이 만료된다.

## 비기능적 요구사항
- 다수의 인스턴스로 어플리케이션이 동작하더라도 기능에 문제가 없어야한다.
- 동시성 이슈가 발생하지 않아야한다.
